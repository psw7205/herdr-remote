# Herdr Mobile Chat Backlog

2026-09-29 기준. 요구와 결정의 기준은 `docs/prd.md`, `docs/adr.md`이고, 확인된 구현·runtime 근거는 `docs/records/verification.md`, `docs/records/integration-findings.md`에 있다. 이 목록은 남은 작업의 순서와 완료 기준을 관리한다. 세부 구현 방식은 착수 시 실제 Herdr/API/agent version을 다시 확인한다.

현재 **Claude Code / macOS의 첫 vertical slice는 로컬에서 검증됐다**. 기존 session 발견, native transcript Chat, 동일 PTY prompt, transcript 응답, retry 중복 방지, stale binding 거부, Bridge 재시작 복구, Terminal fallback이 동작했다. 2026-09-24에는 Funnel 없이 Tailscale Serve HTTPS를 활성화했고(P0-01), 소유자 phone에서 Tailnet HTTPS로 기존 대화 표시, prompt 한 번 전달과 같은 native session 응답, Terminal 표시를 확인했다. 2026-09-28에는 격리 Herdr server에서 pane·session 교체, `/exit` 경합, interrupt, WS 종료, permission 대기, patch↔stock 전환을 실측했다(P0-04~06). 2026-09-29에는 worktree 이동 뒤 transcript 추적(P1-12), 장기 실행 resource 상한(P1-13), Herdr로 새 `claude` session 시작(P1-14)을 구현하고 격리 Herdr에서 확인했다. 실기기 UI 세부와 reconnect는 `in-use`로 사용하면서 확인하고, Codex write 경로는 완료되지 않았다.

상태: `done (날짜)`는 완료 기준을 실측으로 확인한 항목이며 근거를 한 줄로 남긴다. `in-use`는 핵심 경로가 확인됐고 남은 것을 소유자가 사용하면서 확인하는 항목이다. 문제가 보이면 그때 고치며 다른 작업의 선행 조건이 아니다. `blocked`는 외부 조치나 외부 release가 필요한 항목, `todo`는 미착수 또는 검증 미완료, `optional`은 핵심 handoff 이후 기능이거나 착수 조건이 생길 때 하는 항목이다. 우선순위는 의존성과 session integrity를 기준으로 한다.

검증 수준 원칙: single-user 도구이므로 blocker와 자동 실측은 조용히 실패하거나 되돌릴 수 없는 항목에 둔다. 잘못된 process 입력, 중복 dispatch, 사용자 모르게 멈추는 agent, identity·Origin 경계가 여기에 해당하며 [격리 Herdr 환경](../CONTRIBUTING.md#격리-herdr-환경)에서 확인한다. 화면에 드러나고 새로고침·재시도로 복구되는 UI·실기기 동작은 `in-use`로 둔다.

## 계속 범위 밖인 항목

Multi-host, multi-user 계정/조직, public internet 배포, 자체 agent runner, conversation DB,
full IDE·source editor, mobile Git commit/push/merge는 현 PRD의 non-goal이다.
이 목록에서 우선순위를 받은 기능이 아니다.

**의도:** 기존 Herdr session의 무결성을 먼저 증명하고, 눈에 보이는 UI 문제는 사용하면서 고친다.
**추천:** Codex parser(P1-02)를 먼저 검증하고 조건부 binding(P1-01)으로 write를 연다 — 이유는 Claude 경로의
P1-12~14가 닫혀 남은 핵심 확장이 두 번째 agent이고, P1-02는 P1-01의 write gate 없이 read-only로 먼저
검증할 수 있기 때문이다. Codex가 검증되면 ADR-037의 kind allowlist에 추가한다.
`in-use` 항목(P0-02, P1-04~06, P1-08, P1-09, P1-13, P1-14)은 순서와 무관하게 사용 중 문제가 보일 때 고친다.
P0-04는 새 Herdr release가 나오면 rebase부터 진행한다.
